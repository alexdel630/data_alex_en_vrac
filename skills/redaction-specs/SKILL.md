# Rédaction de spécifications

1. Si le besoin est flou, commence par 3 à 5 questions de cadrage, ou propose le skill `grill-me`.
2. Rédige avec cette structure :
   - **Contexte et problème** : pourquoi maintenant, pour qui.
   - **Objectifs** mesurables et **hors périmètre**.
   - **Utilisateurs et parcours** principaux.
   - **Exigences fonctionnelles** : tableau ID / exigence / priorité (MoSCoW) / critère
     d'acceptation vérifiable (« Étant donné… quand… alors… »).
   - **Exigences non fonctionnelles** : performance, sécurité, accessibilité, compatibilité,
     avec des valeurs chiffrées.
   - **Contraintes** et **dépendances**.
   - **Risques** et hypothèses.
   - **Questions ouvertes**, avec un responsable.
3. Une exigence = une phrase testable. Bannis « rapide », « simple », « intuitif » sans critère.
4. Ne décide pas à la place de l'utilisateur : marque **[À VALIDER]** toute hypothèse de ton cru.

Le modèle `modeles/ingenierie/cahier_des_charges.docx` de ce dépôt suit la même structure.
